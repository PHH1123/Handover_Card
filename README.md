# Handover Card

**말로 남긴 인계를, 상대의 언어로 정리된 카드로.**

비동기 음성 인계 서비스입니다. 인계자가 하던 말을 그대로 녹음해 올리면
전사 → 번역 → 요약을 거쳐, 인수자가 자기 언어로 읽을 수 있는 **인계 카드**가 만들어집니다.

- 서비스: `https://handover-card.o-r.kr`
- API 문서(Swagger): `https://handover-card.o-r.kr/swagger-ui/index.html`

---

## 어떤 문제를 푸나

교대 근무나 프로젝트 인수인계에서 정보는 대부분 **말**로 오갑니다. 그런데 말은 남지 않고,
글로 정리하려면 시간이 들고, 인계자와 인수자가 쓰는 언어가 다르면 그마저도 어렵습니다.

| 흔한 상황 | 지금까지 | Handover Card |
| --- | --- | --- |
| 인계자와 인수자의 근무 시간이 겹치지 않음 | 실시간으로 만날 때까지 대기 | 녹음해 두면 상대가 아무 때나 확인 |
| 두 사람의 언어가 다름 | 번역기에 붙여넣기, 뉘앙스 유실 | 업로드 시 원본/대상 언어 선택 → 번역본 자동 생성 |
| 말한 내용이 길고 산만함 | 받아 적거나 기억에 의존 | 핵심 항목으로 요약된 카드 |

## 어떻게 동작하나

```mermaid
flowchart LR
    A["음성 업로드<br/>(파일 또는 브라우저 녹음)"] --> B[전사 STT]
    B --> C[번역]
    C --> D[요약]
    D --> E[인계 카드]
    E --> F["팀원 조회 · 사람이 직접 수정"]
```

업로드 즉시 `202 Accepted`로 응답하고 파이프라인은 뒤에서 돕니다. 사용자는 처리가 끝날 때까지
화면을 붙잡고 있을 필요가 없고, 카드 상태(`PENDING → PROCESSING → COMPLETED / FAILED`)로
진행 상황을 확인합니다. 실패한 카드는 재처리할 수 있습니다.

## 주요 기능

**인계 카드**
- 음성 파일 업로드 또는 브라우저에서 바로 녹음 (별도 앱 설치 없음)
- 6개 언어(영어·한국어·일본어·중국어·스페인어·베트남어) 간 번역
- AI가 만든 전사/번역/요약을 **작성자가 직접 고칠 수 있음** — 모델이 틀린 고유명사나 수치를 사람이 바로잡고, 고쳐진 카드가 최종본이 됩니다
- 처리 실패 시 재처리, 카드 삭제

**팀**
- 팀 생성 · 가입 신청 · 승인/거절 · 신청 취소
- 리더 위임, 멤버 강퇴, 팀 탈퇴/삭제
- 카드는 **작성자 · 지정된 수신자 · 같은 팀 멤버**만 조회 가능

**계정**
- 이메일 회원가입 / 로그인
- Google · GitHub 소셜 로그인 (어느 쪽으로 로그인하든 이후 흐름은 동일)
- JWT Access/Refresh 토큰, Refresh Token 회전 및 재사용 감지 시 폐기

## 기술 스택

| 영역 | 사용 기술 |
| --- | --- |
| Backend | Java 25, Spring Boot, Spring Security, Spring Data JPA |
| DB | MySQL (운영 RDS) |
| Storage | AWS S3 (개발은 MinIO) |
| AI | OpenAI `gpt-4o-mini-transcribe`(STT), `gpt-4o-mini`(번역·요약) |
| Infra | 가비아 클라우드 서버 1대, Docker, Nginx + HTTPS(Let's Encrypt) |
| Frontend | SPA(같은 서버에서 정적 서비스) + 확인용 서버 사이드 화면(Thymeleaf) |
| Docs | SpringDoc OpenAPI (Swagger UI) |

## 설계에서 신경 쓴 것

**AI 호출을 갈아 끼울 수 있게 추상화했습니다.**
전사·요약 모두 인터페이스 뒤에 두고 `mock` / `openai` 구현을 설정으로 고릅니다. 덕분에 테스트는
네트워크 없이 돌고, 로컬 개발에서 API 비용이 새지 않으며, 나중에 다른 모델이나 실시간 스트림
기반 전사로 바꿔도 애플리케이션 코드는 그대로입니다.

**개발 환경이 운영 경로를 그대로 탑니다.**
음성 저장소를 로컬 디스크로 개발하면 S3 코드가 배포 전까지 한 번도 실행되지 않아, 권한·키
네이밍 문제가 전부 운영에서 처음 터집니다. 그래서 개발에서도 MinIO를 띄워 **엔드포인트만 다르고
타는 코드는 같게** 두었습니다.

**AI 결과를 사람이 고칠 수 있게 했습니다.**
전사와 번역은 틀릴 수 있고, 인계 내용은 틀리면 안 되는 정보입니다. 모델 정확도를 올리는 것과
별개로, 사람이 최종 책임을 지는 경로를 제품에 넣었습니다.

**소셜 로그인은 확인된 이메일만 신뢰합니다.**
공급자가 소유를 확인해 준 이메일(Google `email_verified`, GitHub verified 주 이메일)일 때만 기존
회원과 연결합니다. 그렇지 않으면 남의 주소를 적어 둔 소셜 계정으로 기존 회원에 올라탈 수 있습니다.

## 향후 확장 방향

> 아래는 상용화를 가정한 계획이며, 현재 구현 범위가 아닙니다.

**1. 알림 — 비동기의 나머지 반쪽**
카드는 사용자가 화면을 떠난 뒤에 완성됩니다. 처리 완료와 새 카드 도착을 Slack·메일로 알려
"폴링해서 확인"을 없앱니다. 파이프라인 완료 이벤트에 채널 어댑터를 붙이는 구조라 현재 설계를
그대로 확장할 수 있습니다.

**2. 실시간 통화도 인계 카드로 — Agora RTC**
영상 통화 기능을 더하는 게 아니라, **통화를 입력 채널로 추가**하는 것입니다.
RTC 스트림을 실시간 전사해 지금과 같은 번역·요약 파이프라인에 태우면, 동기로 이야기하든
비동기로 녹음하든 산출물은 하나의 인계 카드로 모입니다. 전사 구현체를 교체하는 형태라
`transcription.provider=agora` 자리가 이미 열려 있습니다.

**3. 팀 · 조직 단위 워크스페이스 (B2B SaaS)**
팀 단위 공유는 이미 동작합니다. 기업 도입을 위해 남은 것은 기능이 아니라 **신뢰**입니다.
테넌트 간 데이터 격리, 음성 원본 보관·파기 정책, 조직 SSO, 감사 로그 — 음성과 업무 대화를
다루는 서비스라 도입 검토에서 가장 먼저 묻는 지점입니다.

**4. 조직별 용어집 기반 번역 품질**
사내 은어, 프로젝트명, 장비 이름은 범용 번역기가 가장 많이 틀리는 부분이고 인계에서 가장
중요한 단어이기도 합니다. 조직이 쌓은 용어집을 전사·번역 단계에 주입해 정확도를 올립니다.
사용자가 카드를 직접 수정한 이력이 그대로 용어집의 재료가 됩니다.
